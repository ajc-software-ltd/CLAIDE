# M3.1 — DOCX + minidocx Post-Merge Integration Plan

## Objective

`minidocx` engine baseline is already merged into `main`; this phase delivers CLAIDE-side adapter/service/render integration with AI-ready operations and canvas-visible output.

## In scope

- Keep `minidocx` as the baseline DOCX engine now merged in `main` (no new engine-scope expansion in this doc).
- Add CLAIDE `core` adapter boundaries for document operations.
- Support open/edit/save for targeted DOCX workflows.
- Route output to Vulkan render surface through CLAIDE render pipeline.
- Provide AI-facing operations for DOCX workflows.

## Out of scope

- XLSX implementation (M3.2).
- Full PDF/Illustrator workflows.
- SVG authoring tools.
- TTF glyph creation/editing.

## Architecture additions

- `src/core/office/OfficeDocumentService.*`
- `src/core/office/MinidocxAdapter.*`
- `src/core/office/OfficeLayoutBridge.*`
- `docs/m3.1-ai-extension-roadmap.md`

## Acceptance criteria

1. DOCX document can be opened and edited in CLAIDE workflow.
2. Edited DOCX can be saved and reopened.
3. Visible content can be rendered on Vulkan canvas.
4. AI operation endpoints can load, inspect, edit, and render DOCX content.
5. Error paths produce actionable logs and preserve user data.

## Risks

- Upstream `minidocx` is beta; round-trip fidelity may vary.
- Complex OOXML constructs may need staged support.

## Validation

- Integration tests for DOCX open/save round-trip.
- Render checks for text blocks and paragraph layout on canvas path.
- AI contract smoke tests for open/edit/render/save flows.
